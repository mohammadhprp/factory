# Local rejection notes

Search existing local decisions before classifying a duplicate or rejected request. Record a deliberate rejection and its reason in the local task Notes section; set `Status: wontfix` only when that outcome is authorized. Link the relevant local decision or code. A missing prerequisite is blocked or needs-info, not a rejection. Do not close an external issue or notify a reporter.

Use a project-local `.out-of-scope/` decision note only when the rejection is reusable across future tasks. Do not create a note for behavior already implemented; cite the implementation in the task instead.
